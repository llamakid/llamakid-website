Presenter Script — Slides 7–14

Background: JavaScript · ~9 minutes · read naturally, don't rush
Tone: talking to kids — warm, a little playful, lots of eye contact. The WHEN · DO · CHANGE mantra and the demo on slide 14 are your anchors. Text below is a guide — say it in your own words.
Slide 7

Background: JavaScript

0:10

"Alright — yesterday we built the look of a web page with HTML and CSS. Today, we make it come alive. So let's talk about the language that does that: JavaScript."

This is just a title slide — keep moving.

Slide 8

What is JavaScript?

1:00

"Here's the easiest way to think about a web page. Imagine it's like a person.

HTML is the bones — the skeleton that holds everything up. CSS is the clothes and the style — how it looks. And JavaScript? JavaScript is the brain and the muscles — it's what lets the page actually do things and react to you.

So every time you click a button and something happens, or you type and a page responds — that's JavaScript working. It's a coding language, and it's how we give the page its instructions."

🙋 Ask the room: "Can anyone think of something on a website or app that reacts when you click or type?" (Take one or two answers — likes, menus, games. Then move on.)
Slide 9

History

1:00

"A little history. JavaScript was invented in 1995, at a company called Netscape. The whole idea was to let regular people — not just expert programmers — build websites that were interactive and fun, instead of just words sitting on a screen.

And here's a fun fact, because you're going to hear this word all day: 'bug.' A bug is a mistake in your code. So why do we call it a bug? Way back when computers were the size of an entire room, real insects — actual bugs — would crawl inside and break them. Engineers literally had to pull bugs out to fix the computer. And the name just… stuck. So today, when your code breaks, we say you've got a bug."

The bug story is a crowd-pleaser — slow down and enjoy telling it.

Slide 10

JS Then vs Now

0:45

"When JavaScript first came out, people honestly weren't totally sure what to do with it. But fast-forward to today, and it is everywhere — websites, apps, phone games, even the game we're about to build.

And over the years, developers built tons of helpful tools on top of it — you might hear names like React or Next. You don't need to know those today; just know it's the same language from 1995, but now there's a huge community of people all helping each other build cool stuff."

Keep this one light and quick — the framework names are just for flavor.

Slide 12

Let's Reopen the Codebase We Started

1:00

"Let's pull up the project we started earlier. Quick recap: HTML puts things on the page, CSS makes them look good, and JavaScript makes them react.

Now here's a little trick to remember what JavaScript actually does. Three words: WHEN, DO, CHANGE. WHEN something happens — like you click a button — DO some code, and then CHANGE what's on the screen. Say it with me — when, do, change. That's basically every piece of JavaScript you'll write today."

Get them to repeat "when, do, change" out loud — it's the mental model for the whole day.

Slide 11

Get to Know the Dev Environment

1:15

"Every developer has a toolbox built right into the web browser. The most important tool is the console. Think of it like a notepad where you can test out little bits of code — and it's also where the computer tells you when something went wrong. Errors and warnings show up right there.

A couple of shortcuts the pros use constantly:

Cmd or Ctrl + F to find something on the page, and Cmd or Ctrl + D to select the next matching word.

And there's a button called 'Inspect' that lets you peek behind the curtain of any website to see the code that built it."

🖱️ Optional live moment: Right-click any website → Inspect. Show them the real HTML/CSS/JS for 5 seconds. Seeing the "secret code" behind a real site is a great wow moment.
Slide 13

How Do You Add JavaScript to a Webpage?

0:45

"So how does JavaScript actually get onto the page? It's a lot like how we added CSS yesterday — we link to the file. For JavaScript, we use a special tag called the script tag.

It looks like this —" (point at the slide) "<script src="index.js" />. That one little line tells the HTML, 'Hey — go grab my JavaScript file and run it.' Without it, the page has no brain. It just sits there."

Slide 14 ⭐

JS Off vs JS On (DEMO)

2:00

"Okay — let me show you why JavaScript matters. This is a game called Cereal Catcher."

Run the demo in this exact order:
  1. Open cereal-catcher.html with JavaScript turned OFF.
  2. Click Start → nothing happens. Pause. Let it be awkward.
  3. Turn JavaScript ON, reload, click Start → the game plays!

(While clicking Start with JS off:) "Hmm… I'm clicking Start. And… nothing's happening. Weird, right? The button's right there."

(After turning JS on and it works:) "Now watch — I turn JavaScript on, reload, click Start… and there it goes!

Here's the key thing: it was the same HTML and the same CSS the whole time. Nothing about the look changed. The only thing missing before was the logic — the JavaScript. That's the brain we talked about. And that, right there, is exactly what you're all going to write next."

This is your finale — end with energy, then hand off to the building-blocks section (slide 15).
